# AGENTS.md

Compact guidance for OpenCode sessions working on ReqGPT (a.k.a. ThinkingPods / Design Thinking Pods).

## What this project is

Offline-first AI Design Thinking assistant. Two cooperating Python processes:
- `server.py` — FastAPI backend (port 8000): LLM (Ollama), STT (faster-whisper), TTS (Silero), mentor pipeline, session persistence.
- `app.py` — Streamlit frontend (port 8501): chat UI, voice I/O, PRD export, Mermaid rendering. Hardcoded to call `http://127.0.0.1:8000`.

All AI runs locally. Core constraint (see `mentor.py` docstring): **the application does the thinking, the LLM does the talking.** State, checklists, and question planning are deterministic/rule-based; the LLM only converts structured facts into natural language.

## Run / develop

Backend + frontend together (Windows):
```
run.bat            # runs autotweak.py, then starts server.py + streamlit in separate windows
python run.py      # same, cross-platform, in one terminal (Ctrl+C stops both)
```
macOS/Linux: `./run.sh` or `./run_macos.sh` (note: run.sh does NOT run autotweak or set env vars — run.bat is the canonical launcher).

Backend alone: `python server.py`
Frontend alone: `python -m streamlit run app.py`

Diagnostics: `python diagnose.py` (checks imports, FFmpeg, port 8000; expects `C:\Users\bezal\AppData\Local\Programs\Python\Python312\python.exe` — harmless warning elsewhere).

## Required runtime prerequisites (non-obvious)

- **Ollama must be running** (`ollama serve`) before backend starts, or the LLM stays `None` and routes 503.
- **`autotweak.py` must run once** to build the `optimized-pods` Ollama model from `llama3.2:1b`. Without it, `OLLAMA_MODEL=optimized-pods` won't resolve and the backend silently falls back. It also probes cores/RAM and writes a temp Modelfile (deleted after).
- Models: LLM `llama3.2:1b` (or `optimized-pods`), STT `tiny.en` (int8), TTS Silero `v3_en`. Cached under `~/.ollama/models`, `~/.cache/whisper`, `~/.cache/torch/hub`. See `OFFLINE_USAGE.md` for offline setup.
- **No `.env` is checked in** (`.env` is gitignored). Env is set via `run.bat`: `OLLAMA_MODEL`, `OLLAMA_BASE_MODEL`, `WHISPER_MODEL`. Bare `python server.py` uses defaults — fine for dev but skips hardware tuning.

## Architecture gotchas

- **Routing**: `server.should_use_mentor()` sends Empathize/Discovery/`general` pods OR `Design Thinking Coach` mode to `mentor.process_mentor_turn()`; everything else goes to `generate_llm_response()` (full chat history + system prompts per pod/mode). Don't assume all turns hit the LLM the same way.
- **Mentor pipeline does rule-based extraction first** (`RuleBasedExtractor`); LLM extraction is OFF by default and only enables when `MENTOR_USE_LLM_EXTRACTION=true`. Keep extraction deterministic when editing — the 1B model can't reliably do JSON extraction.
- **`enforce_mentor_reply()`** rewrites LLM output that gives advice, asks >1 question, or exceeds 55 words (95 for summaries) back to a template fallback. If the assistant suddenly gives canned questions, this filter discarded the LLM reply.
- **History = two parallel stores**: `conversation_histories` (in-memory `SemanticHistoryRetriever` with TF-IDF inverted index, keyed by username, `MAX_HISTORY` env default 50) inside `server.py`, AND `MentorSession` JSON files in `sessions/` managed by `mentor.SessionManager`. The `/reset` endpoint clears both. They are NOT synced beyond reset.
- **dina_direct.py / design_thinking_coach.py** are standalone CLI voice loops that import `mentor.process_mentor_turn` directly (bypassing `server.py`). Launched via `run_dina_direct.bat` / `run_design_thinking_coach*.bat`. They share the `sessions/` state with the web backend.
- **`use_reqgpt.py` is the legacy/dead path**: loads Mistral-7B + PEFT adapter (~28GB RAM on CPU) from HuggingFace; not wired into the live system. Don't introduce it unless explicitly migrating back to it. Active path is Ollama via `use_ollama.py` / `server.py`.
- **Mermaid rendering** loads the JS from a CDN in-browser (`app.py:render_mermaid`) — the only feature that breaks fully offline.
- **Voice transcription** filters hallucinations (`server.py` `hallucinations` list: "1, 2, 3", "thank you", etc.) and short-circuits to a canned "mic check" reply when a transcript is <30 chars and matches; intended behavior, not a bug.
- **`recovery_monitor.py`** is a read-only, deterministic per-turn classifier for non-linear conversations (topic changes, contradictions, uncertain/"I don't know" answers, multiple unrelated facts). It runs inside `process_mentor_turn` and only *explains* — it never mutates state, never picks objectives, never generates replies. Its `Recovery` section appears in the Developer Console (`Detected Inconsistency` / `Recovery Strategy` / `Clarification Reason`). Actual recovery behavior is the existing machinery: family rotation re-asks fresh angles, SET-overwrite accepts the newer scalar, list fields append-not-replace.
- **`conversation_memory.py`** is the deterministic conversational-context memory layer. A `ConversationMemory` container lives on `SessionData` (persists with the session) and records **open threads** (currently-pursued / asked-but-unanswered fields), **resolved threads** (fields that reached a usable answer), **deferred topics** (unsatisfied fields the user raised out of turn), **acknowledged facts** (summary confirmed → `READY_FOR_TRANSITION`), **summarized facts** (`READY_FOR_SUMMARY`), and **partially answered objectives** (e.g. a rough frequency). `update_conversation_memory` runs inside `process_mentor_turn` before reply generation (so the resume hint reflects the just-completed extraction) and references field keys/statuses only — it NEVER duplicates `ProjectState` values; `ProjectState` stays the canonical knowledge store. `memory_to_prompt_bullets` feeds a `resume_hint` into `module4.PromptBuilder.build_prompt` (rendered as extra instruction bullets) so the LLM builds on unfinished topics instead of restarting them. Developer Console shows the `Memory` section (`Open Threads` / `Resolved Threads` / `Deferred Topics` / ...).
- **`conversation_failure_audit.py`** is the observation-only Conversation Failure Audit (pure stdlib leaf, no mentor/Streamlit imports). Runs at the end of `process_mentor_turn` (after the reply + memory update, before `_build_diagnostics`) and classifies each turn as one or more failures: META_INTENT, REPEATED_INFORMATION, MISUNDERSTOOD_RESPONSE, ABRUPT_TRANSITION, OVER_EXPLORATION, UNSUPPORTED_INFERENCE, MISSED_INSIGHT, MEMORY_FAILURE, SOCIAL_FAILURE, MOVE_SELECTION, or NONE. It is STRICTLY observation-only — it mutates nothing, and only surfaces via the `ConversationFailure` / `ConversationFailureSummary` Developer Console sections, the persisted `SessionData.conversation_failure_summary`, `replay_lab._capture_turn` `failure_*` fields, and `python run_conversation_failure.py`. `diagnostics["Pipeline"]["Objective"]` etc. are untouched; golden conversations stay byte-identical.
- **`developer_console_audit.py`** is the observation-only Developer Console UX audit (pure stdlib leaf, no Streamlit/mentor/developer_console imports). It consumes the render plan that `developer_console.build_render_plan` already produces (flat list of `{kind, key, display_name, text, expanded}` blocks) and measures Navigation (sections per turn, max content depth recovered from rendered-text indentation, expandable/collapsed counts, prompt location), Discoverability (prompt/project-state/extraction/performance visible without expanding), Interaction (clicks to reach Prompt/ProjectState/Memory/ConversationFailure — cumulative-collapsed model, each collapsed block from panel top through the target costs one click), Density (avg chars/section, largest/smallest), and Layout (panel width estimate = longest rendered line, estimated scroll lines, visible sections within a configurable `panel_height_lines`, default 20). It is STRICTLY observation-only: it never imports `developer_console`, never mutates plans or diagnostics, and is NOT wired into `mentor.py`/`server.py` — it only surfaces via `DeveloperConsoleAudit`, `DeveloperConsoleAuditSummary`, `developer_console_diagnostics_section`, and `tests/test_developer_console_audit.py`. Rendering output stays byte-identical.
- **`developer_console.py`** owns ALL Developer Console logic (pure stdlib, no Streamlit). It emits consumer-visible pure models that `app.py` renders: `build_render_plan` → flat list of `{kind, key, display_name, text, expanded}` blocks that `developer_console_audit.py` measures (never change its output shape/semantics), `build_tree_plan(...)` (tree model used by tree tests), `collect_turns`/`select_turn`/`turn_label` (`Turn N` labels ONLY, never assistant text), `CATEGORY_ORDER`/`SECTION_CATEGORIES`/`section_category`, `render_section_text`, `render_timing_lines`, `section_status(key, items, *, timing=None)` → `(SectionStatus, reason)` (deterministic read-only traffic lights; `SectionStatus` is a `(str, Enum)` with lowercase `healthy`/`warning`/`problem`; `status_icon`/`status_label` present them; unknown sections default to HEALTHY), `section_subtitle(key, items, *, timing=None)` (pure, e.g. Performance → duration, Memory → `N fact(s)`, Prompt → `N lines · M words`), `highlight_matches(text, query)` (HTML-escaped string wrapping case-insensitive matches in `<mark class="dc-search-hit">`), `prompt_viewer_stats`/`highlight_prompt` (`.pc-h`/`.pc-hline`/`.pc-list`/`.pc-tok`), and `build_timeline` (see Timeline bullet). Everything reads diagnostics by reference and never mutates them. **The Developer Console UI (`app.py`) is a UI-only consumer**: it renders a VS Code-style IDE inspector as a centered MODAL overlay — `render_developer_console_panel` + `_render_console_overlay` (backdrop `.dc-modal-backdrop` + `.st-key-dc_modal` fixed 80vw/85vh centered, dark, rounded, soft shadow, `dc-pop-in` animation; ESC + click-outside close via scoped `st.html` JS, ↑/↓ navigate nav rows; <1200px → 95vw + collapsible nav). The top-right header cluster is a `Console` toggle button (`dev_console_toggle`, opens `dev_console_open`, default `False`) + a `⋮` popover menu (`dc_header_menu`: Reset View / Open Console / Copy Diagnostics / Export JSON). Inside the modal: `dc_ide_turn` (turn selectbox, persisted via `dev_console_selected_turn`), `dc_ide_search` (filters nav + timeline + auto-selects first match), `dc_ide_view` (segmented `📊 Diagnostics` / `🕓 Timeline` radio, persisted via `dev_console_view`), a nav tree `dc_ide_nav` (~260px; HTML `.dc-nav-row` buttons with status icon + name + subtitle + reason, re-dispatched to hidden `dc_navbtn_{sanitized}` Streamlit buttons so selection survives reruns), and a single-file right pane `dc_ide_pane` opening ONE section at a time (`.dc-ide-tab` + `.dc-ide-body` monospace block; the `Prompt` section renders as a full file editor `_render_prompt_editor` — toolbar with `📜 prompt.txt` tab, `{chars · words · lines · bytes}` stats, `⧉ Copy` button, sticky line-number gutter + `white-space: pre` code, both-axes scroll, syntax highlight; search swaps it for the plain `.dc-highlight` match view). Search results show a `N matches` caption; `Reset View` clears `dc_ide_search`/`dev_console_active`/`dev_console_view`. Streamlit 1.55 DOM: columns are `[data-testid="stColumn"]`, element keys become `st-key-<key>` classes used to scope all console CSS. **Constraint: only `developer_console.py` and `app.py` may change; no producer / conversation / PromptBuilder / mentor / extraction / diagnostics changes.**
- **Developer Console tree tests:** `tests/test_developer_console_tree.py` exhaustively covers the hierarchy, category mapping, search (incl. content search, search-driven auto-expand/collapse, `highlight_matches` escaping, and diagnostics-untouched), expand/collapse + pinning, and byte-identical rendering vs `build_render_plan`.
- **Pipeline Timeline:** `developer_console.build_timeline(turn)` produces a fixed 9-stage read-only timeline (`TimelineStage` nodes: User Message / Memory Extraction / Objective Engine / Recovery / Question Family / Prompt Builder / LLM / Response / Diagnostics), each node carrying `duration_ms` (from `turn.timing`: `extraction_ms`, `objective_ms`, `prompt_ms`, `llm_ms`, `finalize_ms`, `total_ms`; Recovery + Question Family share `lifecycle_ms` so their duration stays `None`), a derived `status` (from the existing `section_status` heuristics plus duration thresholds — LLM >8 s → problem, >3 s → warning; others >10 s / >3 s), `metadata` (curated `(label, value)` pairs e.g. objective/confidence, family, prompt char/word/line counts, model, problems/warnings), and `detail` = rendered diagnostics text of the producing sections. It consumes timing + diagnostics by reference, never mutates them (`tests/test_developer_console.py::TestTimeline`). The **Timeline tab** is a UI-only `st.radio` toggle (`dc_ide_view` → `dev_console_view`) in `render_developer_console_panel` that swaps the section tree for `_render_timeline` — a full-width horizontal IDE-style `st.html` node flow (`.dc-tl-flow` with `.dc-tl-card healthy|warning|problem` + `.dc-tl-arrow` connectors, icon + name + wall-time + status emoji, metadata chips, and a native `<details>` that discloses that stage's diagnostics; the modal search filters the cards). It complements (never hides) the Diagnostics tree, which returns when "📊 Diagnostics" is selected.

## Env vars (defaults in parens)

- `OLLAMA_MODEL` (`optimized-pods`) — primary LLM model the backend looks for via `ollama.show`.
- `OLLAMA_BASE_MODEL` (`llama3.2:1b`) — fallback if primary is missing; also the base `autotweak.py` builds `optimized-pods` from.
- `WHISPER_MODEL` (`tiny.en`) — larger = better STT accuracy, more RAM.
- `MENTOR_USE_LLM_EXTRACTION` (`false`) — enable LLM JSON extraction in mentor pipeline; flaky on small models.
- `MAX_HISTORY` (`50`) — in-memory conversation history cap per username.

## Conventions

- No test suite / lint / typecheck config in the repo. Verify edits by running `python diagnose.py` and `python server.py` then hitting `/health` and `/tts/test`.
- `MentorSession` JSON lives in `sessions/` (gitignored as a whole dir but dirs are auto-created); filenames are `{safe_user}_{safe_project}_mentor.json` with non-alphanumerics stripped (`SessionManager.get_filepath`).
- Streamlit session files in `sessions/` are frontend-only and separate from mentor JSON — don't conflate when debugging state.
- Frontend↔backend payloads pass reply text in the URL-encoded `X-Reply` / `X-Transcript` response headers, audio in the body. Preserve this contract when adding endpoints.
- Module ogging uses `print` everywhere (production style of this repo); avoid adding `logging` infra that conflicts.
